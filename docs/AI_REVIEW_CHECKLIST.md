# Чек-лист для AI-ревью (AI Review Checklist)

Используйте этот список для быстрой проверки изменений.

## Корректность (Correctness)
- [ ] Все публичные функции имеют аннотации типов.
- [ ] Код обрабатывает краевые случаи (пустой вход, None и т.д.).
- [ ] Логика в `backend/app/` не содержит хаков или временных обходов.

## Тесты (Tests)
- [ ] Новое поведение покрыто хотя бы одним unit-тестом.
- [ ] Тесты в `backend/tests/` проходят успешно.
- [ ] Тесты используют детерминированные данные (например, `FakeEmbeddingProvider`).

## Обработка ошибок (Error Handling)
- [ ] Ошибки выкидывают понятные исключения (ValueError, TypeError и др.).
- [ ] Система не падает с "unhandled exception" в основном цикле.

## Имена (Naming)
- [ ] Имена функций и переменных соответствуют смыслу.
- [ ] Сохранён стиль именования проекта (snake_case).

## Архитектура (Architecture Fit)
- [ ] Новые функции лежат в правильных модулях.
- [ ] Зависимости идут в правильном направлении (см. `ARCHITECTURE_RU.md`).

## Сложность (Complexity)
- [ ] Нет преждевременных абстракций.
- [ ] Код максимально прост и понятен.

## Документация (Docs Alignment)
- [ ] `docs/NEXT_STEP.md` актуален.
- [ ] В `docs/commit-notes/` есть описание изменений.

## Качество коммита (Commit Quality)
- [ ] Изменения касаются только одной задачи.
- [ ] В коде нет закомментированных кусков или отладочных принтов.
