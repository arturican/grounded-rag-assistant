# Commit: sync commit-notes README with real steps

## Цель шага

Убрать из `docs/commit-notes/README.md` dangling references на note-файлы, которые не были оформлены как отдельные чистые шаги и только размывали реальную историю.

## Почему этот шаг выделен отдельно

Это чистый docs-cleanup. Его нельзя смешивать с frontend/demo, API regression или docs sync по запуску проекта, потому что он относится только к качеству навигации по истории коммитов.

## Какое состояние репозитория было до этого

`docs/commit-notes/README.md` ссылался на несколько note-файлов, которых не было в отслеживаемой истории как самостоятельных завершённых шагов:

- `2026-04-14-frontend-demo-page.md`
- `2026-04-14-frontend-ask-readable-error-block.md`
- `2026-04-14-final-verification-and-next-step.md`

Это создавало ложное ощущение, что в истории есть отдельные завершённые коммиты под эти названия.

## Что изменено

- Из `docs/commit-notes/README.md` удалены ссылки на dangling note-файлы без отдельного завершённого шага.
- Добавлена note `docs/commit-notes/2026-04-14-commit-notes-readme-sync.md`, объясняющая этот cleanup.

## Как работает итоговое решение

README каталога `docs/commit-notes/` теперь перечисляет только те шаги, которые действительно оформлены и присутствуют как реальные полезные commit-study notes в репозитории.

## Почему эти изменения нельзя было смешивать с другими

Если смешать такую чистку со runtime-изменениями, будет непонятно, где мы реально поменяли поведение приложения, а где просто убрали ошибочные ссылки в документации истории.

## Какие файлы изменены

- `docs/commit-notes/README.md`
- `docs/commit-notes/2026-04-14-commit-notes-readme-sync.md`

## Какие проверки запущены

- Ручная проверка списка ссылок в `docs/commit-notes/README.md` на соответствие реально существующим note-файлам и завершённым шагам в истории.

## Результат проверки

После cleanup README больше не ссылается на dangling notes и лучше соответствует фактической истории и текущему состоянию каталога.
