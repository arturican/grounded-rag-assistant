# `faf7f09` - API honest-failure regression

## Что появилось

В [backend/tests/test_api.py](/home/art/project/grounded-rag-assistant/backend/tests/test_api.py) добавлен regression-тест для сценария, где пользователь задаёт нерелевантный вопрос и API должен честно отказаться от ответа по контексту. Параллельно в [backend/app/answering.py](/home/art/project/grounded-rag-assistant/backend/app/answering.py) поднят порог `min_score` по умолчанию, а [docs/NEXT_STEP.md](/home/art/project/grounded-rag-assistant/docs/NEXT_STEP.md) переключён на следующий маленький шаг для CLI.

## Как это работает

Новый тест строит маленький локальный индекс через существующий `/index`, а затем вызывает `/ask` с явно нерелевантным запросом `cat`. До этого коммита такой сценарий почти не мог дойти до honest-failure ветки, потому что `FakeEmbeddingProvider` создаёт очень похожие друг на друга положительные векторы, и старый порог `0.05` был слишком мягким. После повышения дефолтного порога user-facing answer flow снова может отличать слабый retrieval от достаточно уверенного.

## Зачем это нужно

Главный принцип проекта звучит просто: лучше честно сказать, что ответ не найден в контексте, чем сшивать что-то “похожее”. Этот коммит закрепляет этот принцип не только в unit-тестах answer layer, но и на API-границе, то есть на том уровне, который уже видит внешний клиент. Заодно он показывает хороший ритм маленьких шагов: сначала нашли дыру в поведении через тестовый сценарий, потом минимально подкрутили порог, не таща в проект лишнюю новую архитектуру.
