# 2026-04-14-cli-tie-order-regression.md

В этом коммите добавлена CLI-регрессия, которая закрепляет детерминированный порядок источников, когда retrieval возвращает одинаковые similarity score.

### Что изменилось

1. **Тесты**:
   - В `backend/tests/test_cli.py` добавлен тест `test_run_cli_returns_tied_sources_in_stable_order_regression`.
   - Тест строит локальный индекс из двух файлов с одинаковым текстом, чтобы получить одинаковые embedding и равные retrieval score.
   - Затем он проверяет, что `run_cli(["ask", ...])` показывает оба источника в стабильном порядке.

### Как это работает

- `index_directory(...)` индексирует два `.txt` файла с одним и тем же содержимым.
- `run_cli(["ask", ...])` проходит тот же пользовательский путь, что и реальный локальный CLI-вызов.
- Поскольку тексты совпадают, retrieval получает tie по score, а проверка подтверждает, что CLI-вывод остаётся детерминированным и не зависит от случайного порядка.

### Зачем это нужно

Это закрывает ещё один пользовательский regression-сценарий из Phase 9. У нас уже есть проверка deterministic tie-breaking на уровне retrieval, а этот тест добавляет гарантию на CLI-visible слой: при одинаковой релевантности пользователь видит источники в одном и том же порядке, а тесты не становятся flaky.

### Как запустить проверку

```bash
python3 -m unittest backend.tests.test_cli -v
```
