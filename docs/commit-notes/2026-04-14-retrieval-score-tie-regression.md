# Commit: test: cover retrieval score tie ordering

## Что было целью шага

Целью шага было зафиксировать детерминированное поведение retrieval-слоя в ситуации, когда несколько чанков получают одинаковый similarity score для одного и того же запроса. ## Как работает новый тест

Новый тест использует уже существующий `FixedEvaluationEmbeddingProvider`, который позволяет заранее задать эмбеддинги для конкретных текстов. Это делает сценарий полностью детерминированным и независимым от внешних моделей.

В тесте задаётся:

- один запрос `tie-break query` с эмбеддингом `[1.0, 0.0, 0.0]`;
- один чанк с более высоким score;
- четыре чанка с одинаковым score относительно того же запроса.

За счёт одинаковых эмбеддингов для четырёх чанков мы получаем строго одинаковый cosine similarity. После этого тест проверяет, что `InMemoryRetrievalStore.search()` сортирует результаты ровно так, как сейчас реализовано в [backend/app/retrieval.py](/home/artur/project/grounded-rag-assistant/backend/app/retrieval.py):

1. сначала чанк с более высоким score;
2. затем чанки с равным score по возрастанию `chunk_index`;
3. если `chunk_index` тоже равен, используется `chunk_id` как финальный tie-break.

Ожидаемый порядок в тесте такой:

```python
[
    "chunk-top-score",
    "chunk-lower-index",
    "chunk-alpha",
    "chunk-zeta",
    "chunk-higher-index",
]
```

Он специально устроен так, чтобы проверить все части ключа сортировки `(-score, chunk_index, chunk_id)`.

## Почему решение сделано именно так

Решение опирается на уже существующий стиль тестов в `backend/tests/test_retrieval.py`:

- используется локальный deterministic provider;
- создаются реальные `DocumentChunk`;
- вызывается настоящий `store.search(...)`;
- утверждения формулируются явно через ожидаемый порядок `chunk_id`.

Я не менял `backend/app/retrieval.py`, потому что новый тест показал, что текущая реализация уже ведёт себя правильно. Это соответствует правилу проекта: не менять production-код, если тест не выявил реальную проблему.

## Ограничения

Тест покрывает именно детерминированную сортировку на уровне `InMemoryRetrievalStore.search()`. Он не оценивает качество самих эмбеддингов и не говорит о semantic relevance в реальном ML-смысле. Это сознательное ограничение: шаг направлен на стабильность и воспроизводимость, а не на улучшение retrieval quality.
