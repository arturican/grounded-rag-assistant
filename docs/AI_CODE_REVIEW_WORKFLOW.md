# Процесс рецензирования (Code Review Workflow)

Этот файл описывает, как проводить проверку изменений, внесённых Codex.

## 1. Подготовка к ревью
Перед тем как смотреть код:
- Прочитай `docs/NEXT_STEP.md`, чтобы понять цель текущего шага.
- Убедись, что текущий шаг соответствует `docs/ROADMAP.md`.

## 2. Анализ изменений
- Сравни намеченное поведение (из `NEXT_STEP.md`) с реальным кодом.
- Проверь, что в `backend/app/` добавлены только необходимые изменения.
- Убедись, что новые функции имеют type hints.

## 3. Проверка на регрессии
- Запусти все тесты проекта: `python3 -m unittest discover backend.tests`.
- Проверь, что новые тесты покрывают именно тот сценарий, который был изменён.
- Если в `backend/app/` была изменена логика — старые тесты ДОЛЖНЫ быть обновлены или дополнены, но не должны просто удаляться.

## 4. Качество тестов
- Тесты должны быть узкоспециализированными (unit-тесты).
- Тесты не должны зависеть от внешних API или тяжелых библиотек (используй Fake провайдеры).
- Проверь, что для CLI-тестов используются соответствующие моки (`stdout`, `argv`).

## 5. Проверка документации
- Убедись, что `docs/NEXT_STEP.md` обновлён на следующий шаг после успешного выполнения текущего.
- Проверь, что в `docs/commit-notes/` добавлена новая заметка о текущем коммите.
- Заметка в `commit-notes` должна объяснять "Зачем", а не только "Что".

## 6. Написание рецензии
- Пиши замечания коротко и по делу.
- Используй шаблоны: `Critical: <text>`, `Correctness: <text>`, `Suggestion: <text>`.
- Если всё хорошо, подтверди, что шаг выполнен корректно.
