# AI Agent Playbook

## Принцип работы агента

- Работать маленькими завершенными шагами.
- Один шаг = одна задача = один commit = одна commit note.
- Сначала читать код и docs, потом менять.
- Любое изменение подтверждать проверкой.

## Как выбирать следующий шаг

1. Если есть `stepes.md`/`STEPS.md` - идти сверху вниз.
2. Если их нет - брать текущий шаг из `docs/NEXT_STEP.md`.
3. Перед реализацией проверить, не сделан ли шаг уже.
4. Если шаг уже закрыт - кратко зафиксировать факт и обновить `docs/NEXT_STEP.md` на следующий.

## Как проверять согласованность backend/frontend/docs/tests

- Backend API контракт (`/health`, `/index`, `/ask`) должен совпадать с frontend types и API client.
- Поля `answer`, `used_context`, `sources` должны одинаково трактоваться в API, UI и тестах.
- README и `docs/ARCHITECTURE_RU.md` должны описывать текущее поведение, а не старое.
- `docs/NEXT_STEP.md` всегда указывает один конкретный следующий маленький шаг.

## Как отличать баг от допустимого упрощения

Считать багом:

- нарушение контрактов данных;
- непредсказуемые 5xx в user-flow там, где ожидается управляемый отказ;
- потерю метаданных источника;
- расхождение реализации с текущим docs-контрактом.

Считать допустимым упрощением:

- детерминированный fake-embedding в локальной сборке;
- in-memory retrieval на текущем этапе roadmap;
- минимальный UI без визуального polish.

## Что делать при нахождении ошибки

1. Воспроизвести и зафиксировать фактическое поведение.
2. Определить минимальную точку исправления.
3. Добавить/обновить regression test.
4. Сделать локальный фикс без расширения scope.
5. Прогнать узкие релевантные проверки.
6. Обновить docs при изменении поведения.
