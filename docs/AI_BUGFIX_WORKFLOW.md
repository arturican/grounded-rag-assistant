# AI Bugfix Workflow

## 1) Воспроизведение проблемы

- Зафиксировать входные данные, команду и фактический результат.
- Убедиться, что это баг, а не ожидаемое упрощение текущей фазы.
- Сформулировать контракт, который нарушен.

## 2) Локализация причины

- Найти минимальный участок кода, где поведение расходится с контрактом.
- Проверить связанные тесты и docs.
- Не менять архитектуру, если локального исправления достаточно.

## 3) Минимальный фикс

- Исправлять только причину сбоя.
- Не добавлять побочные улучшения в том же шаге.
- Сохранять текущие API-контракты, если нет критической причины менять их.

## 4) Regression test

- Добавить один узкий тест на найденный сценарий.
- Тест должен падать до фикса и проходить после фикса.
- Не дублировать покрытие, если уже есть близкий тест - лучше расширить его точечно.

## 5) Проверка, что ничего не сломано

- Запустить минимально необходимый набор тестов:
  - модульный тест на фикс;
  - ближайшие интеграционные проверки слоя.
- Если изменение затрагивает API/UI, прогнать соответствующие проверки frontend/build.

## 6) Документация и завершение шага

- Обновить docs, если изменилось наблюдаемое поведение.
- Добавить commit note в `docs/commit-notes/`.
- Обновить `docs/NEXT_STEP.md` на следующий маленький шаг.
